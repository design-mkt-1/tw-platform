# UI/UX audit — 2026-09-10

A full pass over the Top-Win demo for four things the owner named: **mobile fit**, **intuitive**
(every control does what it promises), **not cluttered**, and **logical and clear**. Every item
below has a file line or a browser measurement behind it. Where a claim came from reading code
rather than from the page, the row says so.

## How it was done

- **Four code auditors** read disjoint areas: shell and panels, casino home, sport, and
  primitives/CSS/axe output. Each was briefed with the full `ui-ux-pro-max` rubric
  (`quick-reference.md`, 119 UX guidelines; `pro-rules.md`, the pre-delivery checklist) and ten
  targeted searches from the skill's own data, such as `"touch target spacing mobile" --domain ux`
  and `"modal drawer dismiss focus" --domain ux`.
- **A browser pass** in Chrome on the dev server. Chrome's window could not be resized, so the
  app was loaded into a same-origin iframe of exact size — 390x844, then 360, 375, 414, 430, plus
  the bare 1912-wide window. The harness was checked against a known number first: `/` at 390
  measured 5598 tall, the figure `sweep-2026-09-12.md:139` records.
- **`scripts/review.mjs` and `scripts/a11y.mjs`** against the dev server.
- Findings already carried by `docs/next-session.md`, `docs/sweep-2026-09-10.md` or
  `docs/sweep-2026-09-12.md` are marked *recorded* and were not counted as new.

IDs: `B1`–`B4` are the four code auditors, `M` is the browser pass.

Status: **fixed** (in this pass), **owner** (needs a decision, see the last section),
**recorded** (already on file), **pass** (checked, fine), **dev-only**.

## The four decisions the owner took during the audit

| Question | Decision |
| --- | --- |
| Pages at 360 and 375 are clipped; 414, 430 and desktop stretch | Fluid below 390, a centred 390 column above. At 390 nothing moves. |
| 25 links lead to a page that has no header and no nav | Keep the links. The 404 keeps the header and the bottom nav. |
